## Core objective

FTFN exists to make the path from frontier claim to real-world consequence legible. v0.4 established the canonical coverage, authority, encyclopedia, project and place architecture. v0.5 turns that architecture into an open research fieldbook: readers can now see where an exact artifact may be acquired, which question it could answer, how it must be reviewed, which cases can be compared, and how every topic's unresolved work connects.

The fieldbook does not manufacture progress. Authority, commitment, implementation, validation, acceptance, repeated operation and comparable outcome remain separate evidence states. A prepared packet is not an artifact. A research mission is not an answer. A playbook is not a decision. A comparative dossier is not a performance comparison. A topic workbench is not an adjudication.

## Evidence Fieldbook architecture

The v0.5 relationship chain is deliberately directional:

1. **Acquisition packets** identify a Candidate official rail, four artifact targets, required metadata, admissibility tests, invalid substitutions, a reviewer and a stop rule.
2. **Research missions** retain the exact Phase 116 question, required evidence, geography and completion rule, then join it to method, period, denominator, contextual Published evidence, named projects and places, and exact topic-and-stage acquisition packets.
3. **Verification playbooks** define the procedural tests for the eight conversion stages, twelve claim types and ten quality dimensions.
4. **Matched dossiers** compare evidence structures, identities, periods, methods, denominators and stopping points without inventing a common performance measure.
5. **Topic workbenches** make all applicable fieldbook objects reachable from each of the seventeen canonical topics without replacing the coverage file or encyclopedia chapter.

All joins use stable IDs. Titles, aliases, keywords, substrings and fuzzy similarity are not evidence-membership rules.

## Publication boundary

v0.5 is a public research-method and navigation edition. It admits zero exact artifacts and creates no source fact, signal, receipt, evidence-gate decision, observation, project advance, operating result, outcome, score, ranking, forecast, recommendation or causal finding.

Local completion does not authorize a GitHub push, public access change, hosted deployment, DNS change or domain publication. Those remain separate owner-controlled decisions.

## Next evidence-deepening priorities

The next work should use the fieldbook rather than add another parallel architecture layer:

1. **Operate the September 1 evidence gate on its date.** Review `60-CYCLE-LOUISIANA-STARLINK-ADOPTION` against current official primary sources, create a dated receipt even for No Material Change or a bounded blocker, and propagate the result through every assigned record.
2. **Close the twelve acquisition coverage gaps.** Add only official rails that cover the missing topic-stage intersection, prepare packets under the Phase 120 contract, and do not infer that a missing packet means a missing artifact.
3. **Run a bounded exact-artifact acquisition batch.** Select the highest-value packet targets tied to named projects, places and mission completion rules; capture the exact record and required metadata; then route it through normal source and signal review.
4. **Adjudicate missions incrementally.** A later dated phase may mark a mission with a bounded answer, explicit evidence gap, inadmissibility decision or blocker only after every acceptance and rejection rule is applied.
5. **Promote Tier B atlas files carefully.** Add governed conversion relationships only when exact project, event, gate and stage records exist; editorial depth alone does not create Tier A status.
6. **Build longitudinal operating and outcome series selectively.** Require stable identity, compatible periods, methods and denominators, visible revisions, and explicit attribution boundaries.
7. **Maintain the fieldbook as living research infrastructure.** Propagate source changes, corrections, mission decisions and newly mapped rails through the acquisition, mission, method, dossier and workbench layers without silently rewriting history.
